# Требования к надежности интеграций AI Gateway

Дата анализа: 2026-09-28. Базовая версия AI Gateway: `8e849f753ea99f845c6b7a3522fa00bd369aa13f` (`test`); рабочее дерево на момент анализа чистое. Документ фиксирует требования к AI Gateway, а не обещает полную совместимость с любой версией внешнего сервера. Статус «частично» означает, что маршрут существует, но конкретный контракт или модель не подтверждены тестом.

## Границы и текущий путь запроса

Рассмотрены Azure OpenAI, Azure Foundry project OpenAI API, Ollama и самостоятельно размещенный vLLM. Для каждого путь начинается в HTTP-обработчиках `/v1/chat/completions`, `/v1/responses`, `/v1/embeddings`, `/v1/completions` и `/v1/models`; далее идут аутентификация, выбор deployment по модели и capabilities, проверки параметров, provider-level pipeline, адаптер, обработка JSON/SSE и передача usage в billing. Наличие публичного маршрута не означает поддержку операции каждым deployment. ## Требования и критерии приемки

**AG-01 · P1 · Контракт capabilities.** Для каждой пары deployment/model операции `chat`, `responses`, `embeddings`, `stream`, `tools`, `structured_output` должны быть явно разрешены совместно на уровне deployment и catalog. Неизвестное состояние capability не должно превращаться в «поддерживается» при onboarding. Причина: общий адаптер поддерживает больше операций, чем произвольный backend. Приемка: table-driven router tests для всех четырех путей, включая отсутствие `tools` в одном слое, неизвестную модель и alias; upstream получает ноль запросов при отказе. Текущее основание: [provider.go:3098-3161,3848-3893](repos/gateway/internal/provider/provider.go), [discovery.go:153-222](repos/gateway/internal/provider/discovery.go).

**AG-02 · P1 · Параметры и tool schemas.** Поддерживаемые поля должны передаваться без потери смысла; неподдерживаемые поля получают стабильную ошибку с `param`. Для Ollama сохраняются `minimum`, `maximum`, `exclusiveMinimum`, `default` и валидная `$schema`; неверные схемы отклоняются. Для Azure и совместимого пути не следует менять `tool_choice`, `strict`, `response_format`, `reasoning_effort` без подтвержденного профиля модели. Приемка: снимки outbound JSON и негативные тесты на неподдерживаемые опции; tool schema OpenCode проходит до адаптера, невалидная — нет. Основание: [ollama_tools.go:11-174](repos/gateway/internal/provider/ollama_tools.go), [parameters.go:191-255,541-568](repos/gateway/internal/provider/parameters.go).

**AG-03 · P1 · Поток инструментов и reasoning.** SSE должен передавать role, `reasoning_content`, текст, native `tool_calls`, `finish_reason` и terminal usage согласованно. Для моделей, которые выдают полный JSON вызова инструмента как текст, конверсия допустима только для объявленной функции и полной валидной формы; при потоковом запросе применяется буферизованный путь. `max_tokens`/`max_completion_tokens` включают reasoning-токены: исчерпание лимита с пустым видимым текстом должно отражаться как `finish_reason=length`, а не как успешный содержательный ответ. Приемка: тесты JSON и SSE с native tools, текстовым вызовом, коротким лимитом, ошибкой mid-stream и отменой. Основание: [ollama.go:339-523,538-575](repos/gateway/internal/provider/ollama.go), [ollama_text_tools.go:10-49](repos/gateway/internal/provider/ollama_text_tools.go), [chat_stream_fallback_test.go:66-92](repos/gateway/internal/gateway/chat_stream_fallback_test.go).

**AG-04 · P1 · Azure URL и аутентификация.** Режимы `/openai/v1` и deployment-scoped API должны сохранять корректный путь и `api-version`; project URL не должен выдавать себя за resource URL. API key и Entra bearer взаимоисключающи в upstream-запросе; token refresh, 401 invalidation, cloud/audience и отмена через context должны тестироваться без реальных credentials. Приемка: `httptest` для public/government/project/legacy URL, ошибок auth, 401 и redirect; заголовки и token не появляются в логах. Основание: [azure_openai.go:22-98,120-197](repos/gateway/internal/provider/azure_openai.go), [azure_credentials.go:20-60,126-205](repos/gateway/internal/provider/azure_credentials.go).

**AG-05 · P2, по спросу · Foundry native Model Inference.** Отдельный профиль/адаптер вводится лишь при подтвержденном клиентском сценарии. Контракт должен отличать project OpenAI API от native inference по URL, версии, auth audience, tool schema, stream, usage и ошибкам; смешивать их в `azure-openai` без проверки запрещено. Приемка до реализации: зафиксированный backend/version и контрактный тест; после реализации — JSON/SSE, tools, auth, usage и негативные URL tests. Основание текущей границы: [azure_openai.go:163-197](repos/gateway/internal/provider/azure_openai.go), [discovery.go:228-321](repos/gateway/internal/provider/discovery.go), [parameters.go:349-358](repos/gateway/internal/provider/parameters.go).

**AG-06 · P2, по спросу · vLLM профиль.** Для конкретной подтвержденной версии vLLM задать поддерживаемые chat/Responses/embeddings, tool schema, structured output, reasoning и usage; каждое преобразование должно быть явным и обратимо объяснимым. Не выставлять `responses`/`tools` по одному только OpenAI-compatible URL. Приемка: `httptest` контрактный suite с имитацией данной версии и хотя бы один opt-in тест против закрепленного серверного образа; unsupported fields дают 400 до backend. Основание текущего общего маршрута: [provider.go:3971-3983](repos/gateway/internal/provider/provider.go), [openai_compatible.go:578-660,961-1073](repos/gateway/internal/provider/openai_compatible.go).

**AG-07 · P1 · Usage и billing.** Для каждой успешной попытки фиксируются фактические input/output/reasoning/cache tokens, когда backend их сообщает; если точные данные обязательны, неполный upstream usage не должен тихо считаться точным. Budget reserve, commit и cancel привязываются к одному внутреннему execution ID; цена выбирается по versioned catalog и идентичности deployment. После обрыва потока нельзя повторно выставить счет за уже выданный ответ. Приемка: тесты отсутствующего/частичного/нулевого usage, retry/failover, отмены, переполнения и разных цен одинакового публичного model ID; обязательные PostgreSQL integration tests в CI. Основание: [openai_compatible.go:663-735,845-905](repos/gateway/internal/provider/openai_compatible.go), [ollama.go:524-536](repos/gateway/internal/provider/ollama.go), [billing_remote.go:150-180,370-425](repos/gateway/internal/modules/billing_remote.go).

**AG-08 · P1 · Транспорт и ошибки.** Таймауты, размеры ответа, cancellation и закрытие body обязательны; retry/fallback разрешен до первого записанного клиенту SSE event, после этого ошибка завершает поток без новой генерации. Upstream 4xx/5xx должны сохранять безопасный статус/код/`Retry-After` без утечки credentials или prompt. Приемка: `httptest` на timeout, 429, 401, обрыв SSE, malformed JSON, крупный ответ и отмену; метрики отделяют backend failure от client error. Основание: [openai_compatible.go:917-945,1115-1292](repos/gateway/internal/provider/openai_compatible.go), [provider.go:911-1000](repos/gateway/internal/provider/provider.go), [ollama.go:225-245,372-405](repos/gateway/internal/provider/ollama.go).

**AG-09 · P2 · Discovery и управление.** Onboarding должен показывать происхождение capability (`проверено`, `выбрано оператором`, `неизвестно`) и не расширять её из metadata модели. Ошибка `/api/show`, `/v1/models` или project discovery не должна подменяться догадкой. Изменения deployment применяются атомарно с revision check и доступны для отката. Приемка: тесты отсутствующих/устаревших metadata, pagination, конфликтов revision и rollback. Основание: [discovery.go:49-150,153-222,228-321](repos/gateway/internal/provider/discovery.go), [model_onboarding.go:42-75,120-194](repos/gateway/internal/provider/model_onboarding.go).

## Совместимость, безопасность и границы

Публичные `/v1/*` DTO сохраняются. Новые режимы провайдера требуют явного opt-in в конфигурации и отдельного migration note; старые deployment не переклассифицируются автоматически. Ключи остаются в credential store, bearer не переносится между endpoint при fallback. URL валидируются до сетевого запроса; redirect для Azure не следует автоматически. Не сохранять prompts/tool arguments в диагностике или тестовых фикстурах, составленных из реальных пользовательских запросов. Основание: [azure_openai.go:38-98](repos/gateway/internal/provider/azure_openai.go), [config.go:430-525](repos/gateway/internal/config/config.go).

Не входят в текущий этап: новые публичные image/audio/video/agents API, универсальный provider passthrough, копирование чужой архитектуры, изменение тарифов, деплоймента или секретов. Эти возможности требуют отдельного бизнес-сценария. Native Foundry и версия-специфичное поведение vLLM остаются **неподтвержденными** до доступа к тестовому backend. Лицензионное условие: в реализации использовать собственный код и протокольные контракты; любое заимствование стороннего кода требует отдельной правовой проверки лицензии и атрибуции.
